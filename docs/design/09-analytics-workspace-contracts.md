# Analytics workspace contracts

These durable contracts govern the analytics API, workspace, chart elements, release layout and test fixtures. Plan 20 implemented the contracts; this document is their continuing reference. For the implementation history and residual follow-ups, see the [Plan 20 record](../plans/20-analytics-reset.md).

## Read context, density and theme

[Plan 29](../plans/29-analytics-ui-rework.md) defines the repair and presentation contract against locally reproduced Plan 20 failures; [its evidence](../plans/29-analytics-ui-rework.md) distinguishes defects from stale history and permission states. The design PR changes no product behavior.

- Tenant-bound reads share the selected API/auth/tenant and resolved scope, including schema, cursor continuations, conversation/content and `/v1/baselines`. Remote cookie reads always carry `tenant`; local and bearer rules stay unchanged. Resolve browser `win` into absolute bounds or `all=1` before sending it. Scope changes restart paging.
- The current wire schema is heterogeneous: time measures are named objects; artifact lenses are keyed metadata. Normalize names and retain metadata in one client adapter. Choosers respect per-mode fields and per-measure dimensions; general session measures do not imply scatter support. Failed reads are explicit errors/refusals, never empty observations.
- Plan identity selects associated sessions without filtering their usage/events by raw repo/plan identity; original attribution and explicit event filters remain intact. Historical check discovery and selected-check validation use retained-plus-active per-kind names, independently of scorer configuration. Empty ledgers return valid schema/zero coverage. Coverage distinguishes event seconds and receive nanoseconds and exposes recency and attribution gaps.
- Dense operational layout: full viewport width with 12 px desktop/8 px narrow gutters, no centered cap, compact ruled tables/panels, URL-backed editable scope, visible unit/population/basis, chart/table alternatives and retained interaction/accessibility. Longer caveats live in disclosures.
- Document surfaces, chart hosts and shadow roots share one inherited active-theme family. Plot/canvas, controls, tables, legends, tooltips and selections follow it on initial load and theme switch. Remove white fallback surfaces; the light plot surface is off-white. Keep no-build modules, vendored uPlot and first-party SVG/canvas.
- Preserve query budgets and exact population semantics while fixing repeated scans/batching. Plan 29 requires real-history-scale replay in addition to the existing small fixtures; raising the deadline alone is not a repair.

## Range, resolution and budgets

- Owns: how every analytics route treats time windows and output size; the error vocabulary for budgets; deadlines and cancellation; the coverage and effective-window report.
- Contract:
  - **No window cap.** `tooWide`, `maxBuckets` as a window cap, and every `range too wide` response are removed. Every windowed analytics route accepts `all=1`; it starts at the earliest retained fact or rejection applicable to that route, including pre-1970 data, and ends at the resolved `to` (now when absent). `/schema` and exact-entity/content reads have no window to widen. Any ordered RFC3339 bounds within the nanosecond-representable interval are accepted: **1677-09-21T00:12:43.145224192Z through 2262-04-11T23:47:16.854775807Z**, inclusive. This is Go's signed-int64 `UnixNano` boundary used by cursors, `seconds()` and rejection comparisons (`store/analytics.go:122`; `serve/analytics.go:43-46,143`), not a product reporting policy; outside it is 400 `time_out_of_range`. `window: {requested, effective, clipped}` reports a start moved forward to `coverage.first_ts` as `before_first_data`; empty coverage has null bounds and an empty result. Coverage is route/population-specific, never a promise that an archive contains every historical event.
  - **Resolution instead of width.** Resolution capabilities are advertised per route and used by the client. `/query` accepts `bucket=auto`; `/score-series` currently accepts day/week/month and must advertise that distinction rather than inheriting the global auto flag. Publish `/schema.resolutions.routes["score-series"] = {buckets:["day","week","month"], auto:false}` with precedence over legacy global flags. Older schemas use this known route-specific bucket set, never a global-auto inference. Unsupported units return 400 `unsupported_resolution` with `supported_buckets`; budget refusal is 400 `too_many_cells` with `max_cells` and a fitting supported `suggested_bucket`. If month cannot fit, omit that suggestion and send `suggested_action: reduce_splits_checks_or_choose_window`; no automatic scope change or history clipping. The remaining automatic-resolution contract below applies to routes advertising `auto`; other routes retain their implemented negotiation. Existing omission defaults stay unchanged (`/query` remains `none`, `/executions` remains rows-only, routes currently requiring `bucket` still require it). The server chooses the finest fitting unit among `hour`, `day`, `week`, `month`, `year`, then multi-year `bucket_step` values from the deterministic 1/2/5 × powers-of-ten ladder, aligned to calendar boundaries in `tz` (calendar arithmetic, not overflowing multi-century `time.Duration` subtraction). Thus monthly resolution is not a hidden long-history cap. One cell is one bucket × one returned dimension-key tuple × one returned measure/check; the bound uses the **product** of dimension cardinalities, including named unknown/mixed and `(other)` groups. `/schema.budgets.max_cells` defaults to 20,000 (existing `queryRowCap`), may be lowered per request and not raised. Responses report `bucket`, `bucket_step`, `requested_bucket`, `coarsened` (effective unit wider than hour for `auto`) and the cell count. An explicit over-budget unit is 400 `too_many_cells` with `suggested_bucket` and `suggested_bucket_step`; no rows are sliced. If one bucket already exceeds the budget, respond 400 `too_many_series` with `suggested_top` or a request to remove a split/check, instead of coarsening indefinitely or silently dropping a series. On routes advertising `auto`, the client requests finer resolution after zooming with `bucket=auto`; it never changes a split or `top` without an explicit action.
  - **Lists page, they do not truncate.** `/explore` gains `limit` and a keyset `cursor` on `(event_time desc, source_type asc, source_key asc)`, where fact keys are `row_hash` and rejection keys are `id`; `/conversations` and `/executions` keep their cursors. Entity detail collections, activity and score groups also page, each with a published deterministic order. Cursors bind route, tenant, canonical filters, grain, sort, resolved window and a first-page receive watermark; later-arriving rows do not enter that traversal. Scores/derived values may change during rescoring or repricing: responses carry a derivation revision and a changed revision makes continuation 409 `cursor_stale`, offering restart, never gaps or duplicates. Aggregate series coarsen or refuse instead of slicing away newest buckets. The existing 5,000-event conversation cap remains explicit with `truncated` and the whole-run totals; the ledger link opens the cursor-paged events for that session.
  - **Deterministic order** is stated per route in the capability schema (each key and tie-break), including `/distribution` (n desc, key asc) and every entity route.
  - **Deadline, cancellation, concurrency.** Each analytics request runs under a server deadline (`budgets.deadline_s` in `/schema`; the default is set in Phase 3 from measured latency, not guessed here); on expiry the route answers 503 `query_timeout` with `retry` hints (a coarser bucket or narrower window), not a partial body. A cancelled request stops its statement and releases the reader (proved, not assumed: the driver's interrupt behaviour was not verified at Ground). Concurrent heavy reads per tenant are bounded, with 503 `busy` and `Retry-After` beyond it, so an all-time view cannot starve the writer or other readers.
  - **Work is bounded by aggregation, not by window.** Usage measures, summaries, score percentiles/series, distributions and entity/cohort reads aggregate in SQL or from rollups; no handler retains all scanned rows, hashes, scores or values in Go memory. Exact percentile/rank operations may spill bounded database working sets to disk under the same deadline; no approximate percentile is labelled exact. `ScoreSeries` uses joins rather than one bind parameter per hash. Detail histories are paged; scatter samples and population marginals are server-side bounded results. SQL grouping versus rollups and the driver's interruption strategy are open implementation choices; the fixed proofs are row-independent Go heap, cancellation releasing the reader, and the unchanged benchmark p95 contract.
  - **Honest carry-overs.** `partial` (compaction not complete) is emitted by every analytics route with `partial_reasons`, not only `/query` (`serve/analytics_query.go:109-111`); `/series` honours `tz` (it ignores it today, `store/analytics.go:420-471`); `/explore` and `/conversation` events carry a `priced` boolean so an unpriced call is never shown as `$0` by a tokens-and-zero-cost guess (the store keeps `priced` private, `store/conversation.go:34`, `store/analytics.go:971-979`). Responses add a machine-readable `code` beside the existing human `error` string; the existing strings are unchanged.
- Non-goals: a retention policy or deletion of data; changing the p95 bound (it remains the performance contract: a request any UI makes must fall inside what the benchmark covers, so the benchmark's presets gain all-time and the bucket domain gains `auto`); any new storage tier.


## Capability schema and coverage

- Owns: the machine-readable statement of what the server can answer, which the UI is driven by, so no limit or capability is hard-coded in a client.
- Contract: `GET /v1/analytics/schema` keeps `measures` and `buckets` unchanged and adds, additively:
  - `budgets`: `max_cells`, `deadline_s`, `top_max`, `page_max`, `scatter_points`, `content_bytes`, `explore_page_max`, heavy-read concurrency, predicate/URL size limits and the retained time range. `resolutions` adds `auto`, year and multi-year step semantics without removing any entry from legacy `buckets`.
  - `grains`: for `time`, `session`, `artifact`, `content`, `plan`, `execution` (later `review`), the identity, measure units/null/time rules, lens domains, supported modes/routes and joins. Content is aggregate/cohort-only, with selected kind/check; it is not a file listing. Each grain has a bounded `id` identity lens for explicit manual mark selection; ordinary lens filters never accept another grain's identity. From Phase 6 each grain also publishes `filters` (every name `/entities?grain=<g>` accepts as a filter, which a frozen source scope may name) and `predicate` (`measures`, `lenses`, and `undefined: [{name, reason}]`), the exact set the cohort resolver answers for it (17.3.1), and `content` is listed as a grain; Phase 4's `where=`/`predicate=` entity filtering is unchanged.
  - `lenses`: each lens with its entity namespace, whether it is single-valued per entity (partitions the population) or set-valued, and the unknown and mixed values it can take.
  - `coverage`: first and last `ts` per fact type, last `received_at`, `compaction`, `pending`, `screen_gaps`, whether a scorer is configured, counts of scored and total distinct artifact content hashes per kind, sessions with and without a derived repo, and pricing/catalogue/tool-kind revisions. This is tenant-wide availability; each query also reports population-specific coverage and its time basis. Compaction/policy removals and unsupported capture are named; no retention-by-age guarantee is invented.
  - `features`: capability flags (`bucket_auto`, `entities_session`, `entities_time`, `entities_artifact`, `entities_plan`, `entities_execution`, `scores_by_lens`, `artifact_content`, `activity`, `cohort`, `exclude`, and, when those servers exist, `actions`, `reviews`). Flags are advertised only when their route/lens contracts are served; later-phase routes are not advertised in Phase 4. `cohort` is advertised only when 17.3.1's publication rule holds, so a server whose cohort resolver answers a subset of what `/schema` offers does not advertise it.
  - The shared filter gains **`exclude=<dim>:<value>`** (repeatable; AND NOT IN, same dimensions as the include filter) so that an exclusion is a real server operation and never the old complement-of-facets workaround.
- Non-goals: a query language; making `/schema` a place to store policy.


## Entities, populations, predicates and activity

- Owns: the entities the workspace explores, their identities, the joins between them, their measures and lenses, and the routes that list and describe them. This is the semantic core that makes scatter, drill-down and cohort links honest.
- Contract, **entities and identities** (all derived from stored facts; no new stored tables are required by the contract):

  | Grain | One row is | Identity | Derived from |
  |---|---|---|---|
  | `session` | an agent conversation | `conversation_id` | facts by `conversation_id` (existing `/conversations` semantics, extended) |
  | `artifact` | a plan file over its life | `(repo_id, path)` | `artifact_version` facts; kind and plan from path (`keys/keys.go:168-186`) |
  | `plan` | a `docs/plans/<plan>/` folder | `(repo_id, plan)` | artifact facts with that `plan` |
  | `execution` | one brief run | `(repo_id, conversation_id, brief_path)` | existing `/executions` rule (`store/analytics.go:521-551`) |
  | `time` | a bucket | `(t, tz)` | existing `/query` |
  | `content` | one scored-content observation for a selected kind/check | tenant-local `content_hash` | `/scores`, `/score-series`; distinct from artifact files |

  A *version* of an artifact is `(repo_id, path, content_hash)`. Scores attach to the tenant-local `content_hash`, which can be shared by several paths/repos (`store/store.go:80-83`); these are different populations, never interchangeable. Entity membership is an in-window fact for that entity (execution membership follows existing in-window brief versions). For a member artifact, latest version is selected over its lifetime by `received_at desc, rowid desc`, matching the existing artifact read; its version timestamp and whether it falls outside the window are shown. The reader exposes lifetime history through paged collections. A plan's associated sessions are sessions active in the scope window that have lifetime artifact facts under the plan. Session repo/model/harness and version attribution are derived over the lifetime before window and lens filters, so brushing does not reassign an entity's provenance; measures remain in-window and are labelled accordingly. Late facts can revise attribution, with the receive watermark/derivation revision making this visible.
- Contract, **joins** (each with cardinality, the attribution rule, and the label the UI must show):
  - *version → writing session*: `conversation_id` of the earliest `artifact_version` fact for that `(repo_id, path, content_hash)` (ties by `row_hash`). Single-valued, so every artifact-grain distribution partitions its population. A later session re-saving identical bytes is counted in `also_seen_sessions` and never moves the version. Label: "earliest observed writing session for this version"; this is captured provenance, not proven authorship.
  - *session → repo*: distinct nonempty `repo_id` values of its artifact and commit facts (never hook rows). The lens is named **`session_repo`** at every grain: the single repo when exactly one, `(multi)` with `repos` listing them when several, `(none)` when absent. `repo_attribution` is `single|multi|none`; these groups partition sessions and their additive measures. A direct artifact `repo_id` remains a separate lens. No session is dropped for missing provenance; unattributed coverage is reported.
  - *session → model*: `models` with shares over deduplicated calls (existing usage deduplication); `session_model` is a nonempty model holding at least 80 percent of all calls, `(mixed)` otherwise, `(none)` for no calls, `unknown` when every call lacks a model. Missing-model calls stay in the denominator. The policy and threshold are published in `/schema`; this is a session association, never author identity. A call's `model` remains a distinct lens.
  - *session → harness*: the most frequent harness over its facts, ties lexicographically, matching the existing mode rule; missing is `unknown`. `harnesses` and `harness_mixed` expose every observed harness when several occur, so a mode is never presented as exclusive provenance.
  - *session → cost*: the existing priced-at-read sum with `unpriced_calls`; a session with unpriced calls reports `cost_usd` as a lower bound with `cost_lower_bound: true`; a session whose calls are all unpriced reports `cost_usd: null`, never 0.
  - *plan → sessions*: sessions with at least one artifact fact under that plan (many to many). `associated_cost_usd` is the sum of those sessions' in-window costs and is **non-additive across plans**: `shared_sessions` counts sessions touching more than one plan, and any total over plans is labelled overlapping. When Plan 22 `action_plan` exists, an additive `attributed_cost_usd` (segment-exact) is offered beside it, never instead of it.
  - *artifact → score*: latest score by `id` per `(content_hash, check)` for the selected version; null with `unscored` when absent. `score_scorer:<check>` carries that row's scorer string (e.g. `jev-1.13.0`); it is not necessarily the screen's scorer or another check's scorer. A scalar `scorer` lens is valid only for a selected check; multi-check charts label each series independently. The model string is recorded, prompt/rubric revision is not, so even a common scorer cannot establish unchanged rubric comparability. Default charts facet different scorers; pooling requires an explicit action and banner. Bands use per-kind/check/scorer all-time baselines over distinct hashes, with strict below-p25/above-p75 and inclusive `mid`; missing baseline is `baseline_unavailable`, not `unscored`.
  - *execution → session*: `conversation_id`. Shape is `complete`, `unreported` or `started` by the existing rule (a commit in the conversation and repo; a report version for the brief's stem). It measures process completion, not success.
  - *cohort links* (below) are the only cross-grain filter, and they resolve through `conversation_id`.
- Contract, **measures by grain** (every measure states unit, `null` rule and time basis; the UI offers an axis or metric only when it is in this table for the grain, from `/schema`):
  - `session`: `cost_usd`, `unpriced_calls`, `model_calls`, `tokens_in|out|cache_read|cache_write|reasoning`, `hook_events`, `commits`, `artifact_versions`, `distinct_content`, `duration_s` (last minus first in-window fact `ts`; observed span, not active work time), `first_ts`, `last_ts` (epoch seconds of the first and last in-window fact; also the default sort key). Measures count over scope like `/conversations`; `spans_window` identifies facts outside it. Lenses: `harness`, `session_model` (+ shares), `session_repo`, `origin` (`agent`, `feedback` for `feedback-*`, `review` for `review:*`; convention-based, not verified authorship), `has_artifacts`. No-call cost is 0; calls with none priced have null cost; partially priced sums are lower bounds.
  - `artifact`: `versions`, `distinct_writing_sessions`, `first_ts`, `last_ts`, `content_bytes` (selected version's full blob length, null with `content_unavailable` when unstored), `score:<check>` for the kind's comparative checks (0 to 1, higher better), and `writing_session_cost_usd`, `_model_calls`, `_tokens_*`, `_hook_events` (the selected version's writing session, aggregated inside the current window; zero observed calls and missing pricing are distinguished). Lenses: `kind`, `plan`, `repo_id`, `harness`, `session_model` of that version's writing session, `source`, `screen_verdict`, and selected-check `scorer` and `band:<check>` (scorer-specific position among peers, never pass/fail). Version metadata exposes every check's scorer independently.
  - `plan`: `artifacts` by kind, `versions`, `sessions`, `shared_sessions`, `associated_cost_usd` (+ `unpriced_calls`), `executions_complete|unreported|started`, `complete_share` (complete / all executions, null with `no_executions` when denominator zero), `design_score:<check>` (latest design version), `span_days`, `first_ts`, `last_ts`. `span_days` is observed first-to-last artifact time, not work duration. Lenses: `repo_id`, `harness`, `session_model` (one vote per associated session, mode with lexical ties for harness, 80 percent dominance for model; `(mixed)`, `unknown`, `(none)` remain distinct). Null/lower-bound cost rules propagate from sessions; summed session cost never becomes plan-exact spend.
  - `execution`: `session_cost_usd`, `brief_score:<check>`, `report_score:<check>`, `ts`. Lenses: `shape`, `plan`, `repo_id`, `harness`, `session_model`.
  - `content` (aggregate/cohort-only, for a selected kind and check): measure `score` (that check's latest score for the hash, 0 to 1; null with `unscored`); lenses `harness`, `session_model`, `repo_id`, `plan`, `scorer`, `screen_verdict` and `band` (scorer-specific position of that score among peers), each derived from the canonical representative file of the hash as `/scores` selects it.
  - `time`: every existing `/query` measure, with `session_repo` and `session_model` on fact-derived measures through their session join. Rejections have no such join and retain `stage`; missing joins return `unsupported_join`. The existing direct `repo_id` on hook/usage measures remains empty for compatibility. Additive sums partition by the single-valued session lenses; distinct counts such as conversations or content can overlap across call-model/time groups and carry `non_additive` plus the unsplit denominator. Numeric time-grain scatter obtains its two aggregate measures from `/entities?grain=time`, not a browser join of unrelated result sets.
- Contract, **routes** (proposed here and owned by this plan; names are the contract):
  - `GET /v1/analytics/entities?grain=<g>` for `session|artifact|plan|execution|time`: shared filter (with `exclude` and `cohort`), `sort=<measure>:asc|desc`, `where=<measure>:<lo>..<hi>` as an AND-only shorthand, `predicate=` for the Boolean grammar below, `fields=`, `limit` (at most `page_max`) and keyset `cursor`. Ties use the full identity. Defaults are session `last_ts desc, conversation_id asc`, artifact `last_ts desc, repo_id asc, path asc`, plan `last_ts desc, repo_id asc, plan asc`, execution `ts desc, conversation_id asc, brief_path asc, repo_id asc`, time `t asc, tz asc`. Rows are `{id, m: {measure: value|null}, l: {lens: value}, flags}`; null measures carry a reason. Every response includes typed `population` metadata described below; totals come from the server, never the returned page.
  - `…/entities?grain=<g>&mode=scatter&fields=<2..4 measures>`: returns every entity in the filter when the population is at most `budgets.scatter_points`, otherwise a **deterministic hash sample** (`sampled: true`, `sample_rule`, `population_n`, `returned_n`; the same query returns the same points), plus `marginals` (fixed-bin histograms of each field over the **whole population**, not the sample). A scatter is only drawn from a response that says what it is.
  - `…/entities?grain=<g>&mode=aggregate&stat=count|sum|percentiles|histogram`: a bounded grouping over that entity population (also `content` for selected kind/check), with `field=` for numeric operations, zero to two schema-supported `dim=` lenses and optional `bucket=auto|<unit>`. Count uses entity identity, sum only schema-marked additive fields within that declared population (plan-associated costs stay non-additive across plans), percentiles/bins use the same null/pricing eligibility as scatter. Responses report groups, typed populations and omitted-group coverage under cell/series budgets; exact percentile computation is server-owned. This supplies score-range predicate counts, artifact band composition and execution-shape grouping without fetching whole lists. At `grain=time`, two-to-four `fields` are aggregate measures over a common bucket/window, returned on a shared bucket grid; missing counts may zero-fill, missing scores never do. Only schema-listed operations are offered; no general expression language is introduced.
  - `GET /v1/analytics/entity?grain=artifact&repo_id=&path=` returns scalar metadata and **one** cursor-paged `collection=versions` ordered `received_at desc, content_hash asc`; each version includes event/receive times, writing session, harness/model, source/sha, screen and per-check scores/scorers. `grain=plan` returns metadata and one of `collection=artifacts|executions|sessions|events`, each with independent `limit`, `next` and population totals. Orders: artifacts `path asc`; executions and sessions as above; events `ts desc, event_type asc, identity asc`. It never embeds unbounded arrays. `grain=session&id=` aliases the bounded existing `/conversation`. Every collection is under the same deadline, receive watermark and revision rules as lists.
  - `/scores` and `/score-series` gain `dim=` (`harness`, `session_model`, `repo_id`, `plan`, `scorer`, `screen_verdict`), `scorer=` and a selected `check=`. Their observation remains **distinct content hashes**, per kind/check (per bucket for series), as on master. First select eligible artifact facts under the window/shared filters/cohort; choose the canonical representative per hash by `ts asc, row_hash asc, repo_id asc, path asc`; then derive its lens. Each hash contributes once to one group, including when identical bytes occur across paths/plans/repos. Lens filters on derived attributes are applied after that representative is chosen. A filtered repo view canonicalises within its eligible facts; it does not claim global authorship. Per-group `n` plus explicitly omitted groups equals the unsplit **same filtered hash population** for that check/bucket; series counts need not sum to window counts because a hash may recur in several buckets. Artifact entity/strip/scatter rows stay file-weighted and show their separate population unit. Scores select the latest row per `(hash,check)` before filtering by its scorer, without reviving historical scores. Group lists page rather than silently dropping top-N values.
  - `GET /v1/baselines?kind=&check=&scorer=&population=content` adds the **new** baseline mode needed by this plan: latest score per hash/check over all retained content of that kind, partitioned by that score's scorer, with `n` and null quartiles when absent. Omitted new parameters preserve the existing latest-file-weighted baseline. All new quality overlays and bands use the explicit content/scorer mode; pooling combines declared groups only on explicit request and retains the caveat that rubric revisions were not captured. `/distribution` gains `dim=harness|session_model|session_repo` beside `model`; call rows use their call harness/model, conversation rows use declared session attributes. Per-group counts only reconcile when all groups and the same eligibility are included; omitted groups and unpriced/lower-bound populations are reported.
  - **`cohort=`** on the routes in 17.3.1 (`/query`, `/distribution`, `/summary`, `/series`, `/conversations`, `/executions`, `/scores`, `/score-series`, `/explore`, `/activity` and `/entities`) is canonical URL-percent-encoded JSON: `{v:1, grain, scope:{from,to,tz,include,exclude}, predicate:<node>, op:include|exclude, source?}`; `op` defaults to `include`. Scope freezes absolute bounds when promoted, independent of the board's relative window. Resolve the **positive source predicate first** to a session set C: session → itself, artifact → selected-version writing sessions, content → canonical representative writing session, execution → its conversation, plan → associated sessions, time → contributing sessions as below. Target queries apply their own scope, then include sessions in C for `op=include` or remove sessions in C for `op=exclude`. Exclusion is set subtraction **after resolution**, never `resolve(not(predicate))`. Source Boolean `not` still complements inside its own grain and can intentionally resolve differently; the tray labels source subtraction separately from board exclusion. Valid empty C includes nothing or excludes nothing respectively, both 200; malformed/unsupported definitions are 400 `cohort_invalid`. Definitions are stateless/re-evaluated under the same budgets; late-data changes carry the derivation revision. The shape of `scope.include`/`scope.exclude`, the per-grain capability matrix, the accepted route set and the association counts are fixed in [17.3.1](#1731-cohort-source-scope-capability-matrix-and-association-reporting).
  - **Time-cohort resolution.** A time-scatter cohort carries `source:{fields:[measure names],bucket:<effective unit>,bucket_step:<effective step>}` from its response; the fixed source window/tz and resolution reproduce its bucket grid. Evaluate the predicate over whole-population aggregate bucket rows, then resolve distinct existing sessions with at least one eligible contributing fact/call in a selected bucket for any named field. Bucket intervals are half-open, intersected with the inclusive source window; deduplicated usage follows the usage measure's identity. Selecting daily cost/commit buckets therefore means “sessions contributing to these buckets”, not a causal pairing of calls with commits. Receipt-time rejection contributors require a recorded conversation ID that resolves to an existing session; missing and orphan associations are counted separately in `population.relation.associations` (17.3.1) and never invented. The target applies its own window to C and explicitly reports expansion to those sessions' other facts/artifacts/plans. Unsupported source operations are disabled with the missing join/reason. Time-cohort evaluation, including bucket aggregation, is inside the same deadline/memory/predicate budgets.
  - **Predicate grammar.** A node is exactly one of `{"and":[nodes]}`, `{"or":[nodes]}`, `{"not":node}`, `{"range":{"measure":name,"lo":number|null,"hi":number|null}}` (inclusive), `{"in":{"lens":name,"values":[strings]}}`, or `{"is_null":{"measure":name}}`. Ranges on null values are false; `not` complements within declared grain/scope. Keys are lexically sorted, numbers normalised, commutative children/values sorted and deduplicated for canonical URLs/cache keys. No executable expressions, recursive cohort references, cross-grain predicates or arbitrary SQL; names are schema-validated. Defaults: 64 leaves, 64 values per `in`, depth 8, four cohorts, 8 KiB **total encoded view URL**, all published. Over-budget selection leaves scope unchanged and offers a smaller region/simpler predicate; never clips. Rectangle union uses `or`, Alt-subtraction `and(previous,not(rectangle))`, additive categories `in`; exclusions negate the same predicate. Explicit individual clicks may use bounded `in(id,…)`; rectangles/cohort regions never expand sampled marks into identity lists. Content cohorts resolve through the same filtered hash representative as `/scores`, to its writing session; file cohorts keep their selected-version rule. The resulting association and possible expansion are named in the tray.
  - **Typed populations.** Each result reports `{grain, unit, scope_n, cohort_n, eligible_n, returned_n, missing_by_reason, relation}` per check/measure where needed. Scope is base window/include/exclude, cohort is after cohort restriction, eligible is after non-null axis/check requirements; `returned_n` is page/sample size. `relation` names a cross-grain mapping and distinct resolved sessions/expanded entities; its members and the association counts are defined in 17.3.1. A selection of 143 sessions can contain 400 artifacts and 12 plans: those counts are labelled and reconcile within their own units. Hash-weighted quality, file-weighted scatter, execution shape, calls, and priced versus unpriced/lower-bound session distributions never share an unlabeled denominator.
  - **Activity and Follow.** `GET /v1/analytics/activity` returns a tenant-bound, shared-filtered, cursor-paged union of session-start, artifact-version, brief-execution and rejection observations (identity includes observation type), ordered `event_time desc, type asc, identity asc`. Session starts and execution rows derive from existing facts; no claim of a session's completion is made. `mode=probe&after=<opaque receive watermark>` returns only counts by observation type and a new watermark, including late arrivals by receive time; it is not an unbounded raw fetch. Both modes obey population coverage, unsupported-filter reporting, deadlines and cancellation. This owned Phase 6 route supplies `river` and Follow instead of a browser merge of independently truncated lists.
  - A measure or lens asked of a grain that does not have it, or a join the table above does not define, is 400 `unsupported_join` with `reason` and `try` (the nearest supported combination). Nothing is silently coerced.
- Conversation timeline coverage: return `returned_events`, `total_events`, `returned_unpriced_calls` and `total_unpriced_calls` alongside existing totals/truncation; returned-event pricing uses the same deduplicated usage identity. ### Cohort source scope, capability matrix and association reporting

Settled by the Phase 6 design clarification (first drafted 2026-11-08, amended 2026-11-18 against the closed Phase 1 to 5 code; provenance: DESIGN.md Provenance Notes) after the first Phase 6 build stopped on three gates. It adds no phase, grain or join. It records in 17.3 the few measures the matrix needs by name (session `first_ts` and `last_ts`, content `score` and `band`), accepts `/series` among the cohort routes, and fixes the shapes 17.2 and 17.3 left open and which pairs a server may and may not publish.

- Owns: the grammar of a frozen source scope, the set of source measures and lenses a cohort must resolve, the routes that accept `cohort=`, and where population, relation and association counts appear in responses.
- Contract:
  - **Scope elements.** `scope.include` and `scope.exclude` are arrays; `[]` means none, and `null` or an absent key stays `cohort_invalid`. An element is `{"lens": <name>, "values": [<string>, ...]}`. `lens` is a member of `/schema.grains[<source grain>].filters`, the list of every name `/entities?grain=<source grain>` accepts as a repeatable include filter and as `exclude=<name>:<value>` (derived lenses and the shared-filter dimensions that grain applies); `values` are exact, case-sensitive strings of that lens's published domain, including its named `(multi)`, `(mixed)`, `(none)` and `unknown` values. It is a structured element and not a `dim:value` string because lens names can contain a colon (`band:<check>`). A value never seen in the tenant is valid and matches nothing. Budgets, applied to the canonical (merged) form: at most 64 elements per list, 1 to 64 values per element, 256 bytes per value (1,024 for an `id` of a composite identity), all published in `/schema.budgets` and counted in the 8 KiB view URL; a board whose chips exceed them cannot be promoted to a cohort, the tray says which budget and offers none, and scope is unchanged.
  - **Boolean meaning.** The source population is the source grain's in-window entities that satisfy every `include` lens and no `exclude` lens. For one lens, the values of all its `include` elements are a union and the entity must match one (OR within a lens, AND across lenses, the shared filter's repeatable-parameter rule). All `exclude` elements naming one lens are likewise a union of removed values, and any matching value removes the entity (AND NOT IN). A set-valued lens (as `/schema.lenses` declares; none in the matrix is) matches when any of its values match. Include applies first, then exclude; the same lens may appear in both. There is no `or` across lenses and no nesting: richer selection belongs in `predicate`. Empty `values` is `cohort_invalid`. Canonical form merges same-lens elements, deduplicates and sorts values lexically, and sorts elements by lens; the canonical key uses it.
  - **Meaning of a lens.** The source population, and every value a predicate leaf reads, is exactly what `/entities?grain=<source grain>` returns for the cohort's frozen window with the scope's `include`/`exclude` supplied as that route's own filters. A lens is therefore the entity attribute `l[<lens>]` that route returns (the lifetime-derived attribute of 17.3's joins for session, artifact, plan and execution lenses; the shared-filter dimension for time), and a shared-filter dimension in `filters` that is not a lens keeps the meaning that route gives it. A frozen cohort reproduces the population the source panel showed because both are one definition. A name that is also a shared-filter dimension takes the grain's lens meaning on that grain's `/entities` route and keeps its legacy meaning on legacy routes. A name `/schema` publishes for no grain is 400 `cohort_invalid`; a published name outside this grain's `filters` is 400 `unsupported_join` with reason `not_defined_for_grain` and `try`. It is never ignored and never listed in `ignored_filters`, because ignoring it would silently change the selected population. At time grain, a filter that does not apply to one of `source.fields` (for example `tool` against `rejections`) is 400 `unsupported_join` naming filter and field in a cohort definition. The time grain's `filters` are the shared-filter dimensions its measures apply, plus `session_repo` and `session_model` only once the time route parses them (17.3 defines them through the session join; Phase 4 does not serve them). An ordinary `/entities?grain=time` request keeps ignoring such a filter but reports it in `ignored_filters` (Phase 6 adds the field; Phase 4 dropped it), and a board promotes only the elements its source panel applied; an element the panel listed as ignored is shown as "not applied here" and not carried into the scope.
  - **Scope is not `op`.** `scope.exclude` narrows the source population before the predicate is evaluated. `op=exclude` subtracts the resolved session set from the target afterwards. Neither substitutes for the other, and the tray labels them separately.
  - **Identity lens `id`.** Values are strings: a session's `conversation_id`; for other grains the canonical compact JSON text of the row's `id` object (keys sorted: artifact `{"path","repo_id"}`, plan `{"plan","repo_id"}`, execution `{"brief_path","conversation_id","repo_id"}`, time `{"t","tz"}`); a content row's hash. Composite identities are therefore never split on a delimiter.
  - **Capability matrix (normative).** A predicate leaf compares the same value the entity row returns in `m` or `l`, lower bounds included with their flag, so a rectangle contains every eligible entity the scatter would draw in it plus the unsampled ones. `range` on null is false and `is_null` is true on null. Dynamic names (`score:<check>`, `design_score:<check>`, `band:<check>`) are validated against the catalogue (unknown: `cohort_invalid`); a known check that does not apply to an entity yields null.

    | Source grain | Predicate measures (`range`, `is_null`) | Predicate lenses (`in`) | Source requirement | Resolves to sessions by |
    |---|---|---|---|---|
    | `session` | every session measure of 17.3, plus `first_ts`, `last_ts` (epoch seconds) | `harness`, `session_model`, `session_repo`, `id`, and `origin`, `has_artifacts` when published | none | itself |
    | `artifact` | every artifact measure of 17.3 (`versions`, `distinct_writing_sessions`, `first_ts`, `last_ts`, `content_bytes`, `score:<check>`, `writing_session_*`) | `kind`, `plan`, `repo_id`, `harness`, `session_model`, `source`, `screen_verdict`, `scorer`, `band:<check>`, `id` | `source.check` names the selected check and is required exactly when `scorer` is used | selected-version writing session |
    | `content` | `score` (the selected check's latest score) | `harness`, `session_model`, `repo_id`, `plan`, `scorer`, `screen_verdict`, `band`, `id` (content hash) | `source:{kind, check}` required | canonical representative's writing session, by `/scores`' representative rule |
    | `execution` | `session_cost_usd`, `brief_score:<check>`, `report_score:<check>`, `ts` | `shape`, `plan`, `repo_id`, `harness`, `session_model`, `id` | none | its conversation |

  - **Matrix is the maximum; the schema publishes the implemented subset.** The matrix is the most a grain can offer. `/schema.grains[g].predicate` lists the subset of its row the server resolves, never less than the measures `/schema.grains[g].measures` lists and the lenses `/schema.lenses` and `/schema.grains[g].lenses` list for `g`. `origin` and `has_artifacts` are the only matrix lenses no phase in this plan owes: they appear in `predicate` only when the server publishes them as lenses, and their absence is an ordinary missing capability. Every other lens and measure in a row is owed by Phase 6 for every grain Phase 6 publishes. Phase 6 publishes `content` (aggregate/cohort-only, selected kind/check; Phase 5 did not list it in `/schema.grains`) beside `plan` and `execution`, so `features.cohort` cannot be advertised over a three-grain subset.
  - **Offer implies resolve; undefined is named.** `/schema.grains[g].predicate` is that subset, and `undefined` the pairs the contract defines as meaningless for it (here only the time-grain lenses), each with a reason. Everything `/schema` offers for a grain as a scatter axis, colour or size, aggregate field, sort or filter must be in its `predicate` list or `filters`, so a mark region the UI can draw is a cohort the server can resolve. A pair the contract defines but a server has not yet implemented is not offered and does not appear in `predicate`; `features.cohort` is advertised only when every grain `/schema.grains` lists (content included) resolves every pair in its `predicate` list, the route rule below holds, and a schema-driven enumeration (not a hand-written list) proves it on the fixture. Unimplemented therefore means the capability is absent from `/schema` (the UI's capability inspector names the absence and the plan phase that supplies it, as it does for any missing feature), while a defined-but-meaningless pair is 400 `unsupported_join` with a reason. Neither is ever an empty result.
  - **Valid, empty, invalid, unsupported.** A well-formed definition whose source set is empty is valid: 200, `relation.resolved_n` 0, nothing included or excluded. Malformed, over-budget (`reason` is `leaves`, `values`, `depth`, `bytes`, `scope_elements`, `scope_values` or `value_bytes`), unknown name or missing required `source` is 400 `cohort_invalid`. A known name the grain does not define, or a route/filter pair the rules above refuse, is 400 `unsupported_join`.
  - **Routes.** `cohort=` is accepted by every analytics route that applies the shared filter: `/query`, `/distribution`, `/summary`, `/series`, `/conversations`, `/executions`, `/scores`, `/score-series`, `/explore`, `/activity` and `/entities` (all grains and modes, artifact included; this adds `/series` to 17.3's list because its `rejections` metric needs the association counts). Every route that does not apply it (`/facets`, which takes only `from`, `to` and `tz` (it parses the shared filter today and silently discards all but the window, which Phase 6 leaves alone), and `/entity`, `/conversation`, `/content`, `/baselines`, `/schema`) answers 400 `cohort_invalid` with reason `route_not_supported`; none may ignore the parameter. Requests without `cohort=` return exactly what they did before.
  - **Target restriction.** A cohort restricts every target the same way: the target's contributing facts are kept (`op=include`) or removed (`op=exclude`) by the `conversation_id` of the sessions in C, exactly as the shared `conversation_id` filter would, before the target computes its measures; entities left with no contributing fact leave an entity-grain population. Derived attributes (session repo/model/harness, version attribution) stay lifetime-derived and are not reassigned by a cohort. Expansion is the target's own population: "143 sessions, 400 artifacts, 12 plans" is the session cohort's `resolved_n` plus the artifact and plan peers' `population.cohort_n`, each in its own unit.
  - **Population and relation reporting.** With a cohort, `population` (17.3 typed populations) is carried as follows: `/entities` list and aggregate modes for session, artifact, plan and execution grains, `/conversations` and `/executions` in the entity's own unit; `/scores` and `/score-series` in `content_hash` per check; every other accepted route that has no `population` object today (`/query`, `/distribution`, `/summary`, `/series`, `/explore`) gains one in `session` unit; `/entities?grain=time` keeps its bucket-unit `population` (buckets are never thinned, so `cohort_n` equals `scope_n`) and carries the session counts as `population.relation.target_sessions = {unit: "session", scope_n, cohort_n}`. Session-unit `scope_n` and `cohort_n` count distinct sessions with at least one eligible in-scope contributing fact before and after restriction (a time bucket grid is never thinned: buckets keep their keys, and their measures count only retained facts); `/activity` carries `population.by_type`, one `{unit, scope_n, cohort_n}` per observation type (`session_start` in sessions, `artifact_version` in versions, `execution` in executions, `rejection` in rejections). The route's own measures keep their existing units and are never equated with these counts. `population.missing_by_reason` is only target eligibility (null axis or check) in the population's unit; association counts never go there. `population.relation` is `{source_grain, target_grain, mapping, op, resolved_n, resolved_unit: "session", associations}` plus `target_sessions` where the route's own population is not in sessions (below); without a cohort `relation` stays `null` as artifact populations already report it; `resolved_n` is `|C|` before the target window, and with `op=include` a session target's `cohort_n` never exceeds it, while with `op=exclude` it is `scope_n` minus the sessions of C inside scope.
  - **Association reporting.** `relation.associations` is an array, empty when the route and source cannot involve unassociated rows, of `{side, contributor: "rejection", unit: "rejection", total_n, associated_n, missing_by_reason: {no_conversation_id, orphan_conversation_id}, treatment}`. A rejection is *associated* when its recorded conversation id names a session as 17.3 defines one (a conversation holding at least one fact other than `session_action`), *missing* when it records no conversation id (ingest precheck rejections carry none), and *orphan* when it records one that names no such session. `total_n = associated_n + no_conversation_id + orphan_conversation_id`. `side: "source"` appears for a time cohort whose `source.fields` include `rejections`: `total_n` is rejections in the selected buckets within the source scope, and only associated ones contributed sessions (`treatment: "selected"`). `side: "target"` appears on every accepted route that can return a rejection count or row (`/query` and `/series` with `rejections`, `/entities?grain=time` with `rejections`, `/summary`, `/explore`, `/activity`): `total_n` is the rejections in that route's own scope before restriction, and `treatment` says what the cohort did to the unassociated ones, `dropped` under `op=include` (they cannot be members of the resolved set) and `kept` under `op=exclude` (nothing is subtracted from them). Selecting a bucket whose only rejections are unassociated is valid and empty, and its counts say so.
  - **Invariants proved by fixtures.** (1) The association identity above holds on every response. (2) Distinct sessions contributed by rejections equal the distinct existing sessions of the associated rows. (3) For a session target over the same scope, `cohort_n(op=include) + cohort_n(op=exclude) = scope_n`. (4) A frozen scope reproduces the source panel's population: for every name in `/schema.grains[g].filters`, the same `include`/`exclude` supplied as ordinary filters to `/entities?grain=g` give the same population total as the cohort's `scope_n`, on a fixture where a session has two harnesses and a model that is `(mixed)` (so a fact-level filter and the derived lens differ). (5) `scope.exclude` and `op=exclude` give different sets on a fixture where they differ.
  - **Phase 4 and 5 alignment owed by Phase 6.** Checked against the closed code: `/schema.grains` publishes no `filters` or `predicate` and no `content` grain; `/schema.budgets` has no scope budgets; session lens filters are not served on `/entities?grain=session` (`harness` there is a fact-level filter, and `session_model`/`session_repo` are not accepted), while 17.3 already requires lens filters on lifetime-derived attributes; artifact entities already filter harness and model on the writing session (with `model=` as the session-model parameter, which stays an accepted alias for `session_model`); `/entities?grain=time` drops its ignored-filter list. Every name in `filters` is accepted under its own name (artifact `session_model` is parsed as `session_model`, with `model=` kept as its alias) and the `exclude=` dimension whitelist is extended to the same names. Artifact cohorts, rejected today as `cohort_invalid`, resolve. The artifact grain's existing `predicate_budgets` key stays and `/schema.budgets` adds the scope budgets, mirroring the same values. Phase 6 brings the session routes to 17.3's meaning for `harness`, `session_model` and `session_repo` on `/entities?grain=session` only (legacy `/conversations`, `/query` and the other legacy routes keep fact-level `harness`), publishes the fields above and adds `ignored_filters` to time entities. These are additive or confined to the new `/entities` route, so requests to legacy routes without `cohort=` stay byte-identical.
- Non-goals: scope elements richer than include/exclude, cross-grain or cross-lens `or`, a stored cohort, new source measures beyond 17.3, and treating an unimplemented pair as an empty result.


## Artifact content

- Owns: read access to the text and history of the artifacts the ledger already stores.
- Contract: `GET /v1/analytics/content?repo_id=&path=&hash=` (bearer `read` scope or session, tenant-bound like every analytics route) returns **complete** version bytes as `text/plain; charset=utf-8`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`. This deliberately extends tenant/read-scope access to promoted blobs, the material search already exposes as snippets. Some blobs have only deterministic precheck and an explicit `unscreened` verdict when no scorer exists; none is claimed safe merely because it is present. Pending/rejected bytes remain unavailable. Assumption 9 records this boundary.
- Non-goals: a diff route (diffs are computed in the browser from two fetched versions, bounded by size); markdown or HTML rendering on the server; content for unstored files; write access.

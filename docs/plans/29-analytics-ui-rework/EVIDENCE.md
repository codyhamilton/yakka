Raw `repo_id` filtering is another **data limitation**, not a zero-count query defect. No original hook had raw repo identity; time/call cost/tools queries filter that column. Use the supported session-repo association for session-grain questions, show `(none)/(multi)` and attribution coverage, and never silently rename a raw-fact filter into a derived session lens. Outcome/review metrics not captured by the ledger stay explicitly unavailable (Plan20 boundary).

Identity/settings/device/profile routes were inspected for their existing connection contract; this plan does not redesign authentication or perform tenant lifecycle actions.

## Theme and density proof

At1920×1080, Chromium measured `main.getBoundingClientRect().width === 1120`. Source `css/app.css` defines `margin:4rem auto`, centered header/footer padding and an overridden1120px cap. `workspace.css` and `charts.css` add padded rounded nested surfaces.

For chart-engine isolation, the existing deterministic gallery ran time-series, scatter/ECDF, bars, ranges, matrix, lanes and treemap through **dark→light→dark**. In dark, every chart host token/frame background was **#1b2734 / rgb(27,39,52)**. Scatter canvas pixel `(2,2)` was **[27,39,52,255]**; in light it was **[255,255,255,255]**, then returned to dark. This proves current engines redraw with theme in Chromium. It does not reproduce Cody's reported deployed white plot background. The demonstrated white controls/header leak (D16) sits outside those shadow roots.

## Replay recipe and limits

The temporary scripts, local captures and database live only in ignored `.scratch/plan29/`; the diagnostic Go test server is removed before the PR. No raw ledger, credentials, cookies, body text or screenshots containing personal rows are committed.

To repeat on another machine, from this worktree:

1. Build current `packages/yakka/cmd/yakka` with the module's Go1.27.1 toolchain. Create disposable directories under `.scratch/plan29/`. Use SQLite's backup API from a read-only source connection; never point the current server at the original legacy directory.
2. Start the binary with `YAKKA_SERVE_DATA=<copy-root>`, a loopback `YAKKA_SERVE_ADDR`, empty/isolated queue and nonexistent client-config path. Initially omit `YAKKA_CHECKS_DIR`. Serve `web/` as a SPA with the committed CSP and proxy `/v1/` to that API, preserving cookies for the authenticated case.
3. Fetch the exact paths in the findings table, recording status, code, elapsed time, rows/check count and returned scope. Start a second fresh-data API for D02. Compare scores with the committed catalogue configured; do not rescore or alter existing data.
4. Visit every route in the output table in Chromium1243, wait for `html[data-idle=true]` and all mounted panels' `data-idle=true`; retain page errors as findings. At1920px record main width, shadow chart backgrounds and document-level computed backgrounds.
5. To expose layered failures only, intercept the browser's schema response and map measure objects to `.name` and lens objects to keys. This diagnostic changes no product files or API results. It made valid trend/Tools queries execute and exposed D09,D12,D13. It is not acceptance proof of a completed adapter repair.
6. Use real Go cookie auth/registry and a populated synthetic owned tenant for D07; local and bearer modes mask missing tenant. First-page limit1 interception is solely to exercise real plan continuation on a tiny fixture. Verify correct-tenant reads succeed and omitted-tenant reads fail. Never record the session cookie.
7. For query attribution, use read-only EXPLAIN QUERY PLAN against the migrated copy and compare call/conversation grain, one/two dimension and page limits. Native SQLite timings identify amplification; they do not substitute for Go HTTP performance acceptance.

No product regression suite is claimed as a fix verification: this PR changes documentation only. Runtime reproduction and its control interventions establish the design's causes; the three phase outcomes specify the future acceptance proof. Production parity is unverified, and the exact remote403 origin was not diagnosed. Neither limitation requires Cody to answer a design-blocking question.

## Goal

Make the workspace engine real: URL-is-state with a panel view-spec codec, a schema-driven panel registry and chooser, a panel frame with the one state/badge vocabulary, a scope bar and coverage strip, board presets as data, named saved boards, off-by-default Follow, the client routes for Start and the named later destinations, and the Start question paths — against a first-party test harness and stub API, with no product code that branches on being under test.

## Contract

- DESIGN.md "Routes" and "URL is the state" are binding. One codec reads/writes every key and preserves unknown keys within the published encoded-URL budget. Scope: `win=<n><h|d|w|m|y|all>` (default `30d`) or RFC3339 `from`/`to` (which take precedence) and IANA `tz`; filters repeat, `exclude` repeats; `ca`–`cd`, `pick`, `sel`, `hide`, `cmp`, `v` and `p<n>` keep their meanings. Window/filter/cohort/compare changes push history; hover and an in-progress drag do not; a committed brush/selection replaces its transient parameter; zoom pushes and clears `sel`; Back restores the full prior scope/cohorts/panels. Compare-period is disabled for `all` with "choose a finite period". No arbitrary finite-period cap.
- A **panel** is registry data `{id, grain, measures, lenses, charts, requires: [features], caveats}` plus a view spec `{grain, measures, split, chart, scope overrides}` serialised in the URL with `p<n>`. `p<n>` is canonical URL-percent-encoded JSON; keep `state.panels` as the raw strings for existing `tests/url-state.test.mjs` compatibility and add the decoded specs beside it. A board is an ordered list of at most 12 panels over one scope; presets are data.
- The panel chooser offers only combinations `/schema` lists for the grain and the registered panel's accepted measures/lenses/charts. Anything else is shown in the capability inspector as unsupported with the reason and the capability's source (this plan's phase, or a design-only plan). A test fails if a registered preset names a panel id with no registry entry.
- Panel states are one vocabulary in every frame, set as `data-state`: `loading` (with in-flight count), `ready`, `empty` (names the filters/cohort/selection that produced zero and offers to clear each), `error` (server message, `code`, retry), `unsupported` (grain/measure/lens not joinable, why, nearest supported choice), `cancelled` (retry, never error), plus non-exclusive badges `partial`, `sampled`, `coarsened`, `clipped`, `lower-bound` through `web/js/charts/badges.js`. Every frame carries `data-idle` when settled.
- Reconciliation: every panel lists applicable scope/cohort/selection chips and "not applied here: X"; "N of M" uses its response's typed `population` and names the unit; totals never come from summing a partial page. Time basis and money rules are DESIGN.md's; unpriced is never `$0`.
- `/schema` is read once per tenant through `transport.schema(tenant)` and drives every chooser; the UI hard-codes no window, bucket, row or cell limit. An older server is normal: an absent feature renders `unsupported` naming the missing feature and what supplies it; a server `range too wide` is shown verbatim with its `retry`.
- Request scheduler: `web/js/core/request-scheduler.js` already caps at four, collapses identical in-flight keys, aborts superseded state and retries `503 busy` with `Retry-After` in `transport.get`; use it for every request, give each panel a stable `stateKey`, and never split, clip or rewrite a window. Show a 400/503 as the server states it with its retry hint as an explicit action.
- Follow: off by default; interval from `yakka-analytics-follow-seconds` (default 30); poll `/activity?mode=probe&after=<watermark>` only while the document is visible; show counts by observation type since the last acknowledged watermark; refetch the feed only on click and advance the acknowledged watermark then; a cancelled/error probe does not advance; no other auto-refresh anywhere. Probe responses are `{mode:"probe", counts:{session_start,artifact_version,execution,rejection}, watermark, ignored_filters}` per `analytics_activity.go`.
- Storage: `yakka-analytics-boards` is a list of named board URLs; the URL stays the source of truth; `yakka-analytics-follow-seconds` is the interval; `yakka-analytics-entity-colours` is owned by the chart registry. Add no other storage key.
- Start question paths are exactly DESIGN.md's list (cost 3, quality 5, plans 3, activity 3, health 1). A path opens its configured board/explorer state, or is disabled with the reason when `/schema.features`/grains lack what it needs. A destination whose preset/explorer is delivered in Phase 10–12 shows a named destination ("delivered in Phase 10: Trends" etc.) and is never dead. Do not invent paths.
- Later routes (`/b/trends`, `/b/compare`, `/b/scatter`, `/b/quality`, `/b/cost`, `/b/tools`, `/b/workflow`, `/plans*`, `/sessions*`, `/artifact`) must render a named destination through the same shell, not not-found and not an empty board. `/` Start, `/b/pulse` (Pulse itself is 9-03), `/ledger`, `/ops` are Phase 9 routes.

## Changes

- `web/contract/url-state.js`: extend decode/encode for `p<n>` view specs as above without changing existing keys, defaults, unknown-key preservation or the current tests' assertions. Keep the codec framework-free.
- `web/js/core/view-spec.js`: pure helpers for the view-spec shape, canonical `p<n>` encoding/decoding, merging a board preset with per-panel overrides, and scope-override precedence (panel override beats board scope). Export the read/write functions app code uses; no DOM.
- `web/js/panels/registry.js`: register/validate/lookup a panel module entry; expose the required shape and a validation that fails on duplicate ids, unknown chart names, or a preset naming a missing panel. `web/js/panels/panel-frame.js`: one `<section>`/frame with title, `data-chart`, `data-state`, `data-idle`, badges, chip slots, chooser slot, capability-inspector slot, and a `setState(state, {message, code, retry, causes})` plus `setPopulation(population)`/`setBasis` API; it calls the panel module's `load({scope, spec, signal, scheduler})` and renders `ready`/`empty`/`error`/`unsupported`/`cancelled` from the result. Do not edit any chart module.
- `web/js/boards/presets.js`: the preset mapping as data. It exports `registerPreset`/`lookupPreset`; the seven non-Pulse presets are rows marked with their delivering phase and no panel list, resolved to named destinations. It reserves `pulse` for 9-03, which registers its five panel ids when its modules load; it does not register `pulse` itself, so no preset names a panel that does not yet exist. `web/js/boards/board.js`: assemble an ordered board over one scope from registry entries + URL specs, at most 12; a missing/unknown panel or an unregistered preset renders a named reason, never a crash.
- `web/js/core/panel-state.js`: the state vocabulary, allowed transitions, and helpers for empty causes and unsupported nearest-choice text. Do not duplicate badge logic from `charts/badges.js`.
- `web/js/core/saved-boards.js`: list/save/rename/delete named board URLs in `yakka-analytics-boards`; saving stores the current URL; opening navigates to the stored URL; the URL remains authoritative. No server.
- `web/js/core/follow.js`: the Follow state machine and probe loop described above, with an explicit `probeNow()`/`acknowledge()` surface used by the river panel and tests; it must not poll when hidden, must not advance on abort/error, and must not animate or sleep in tests.
- `web/js/core/router.js`: parse path+query into a route record, dispatch Start/board/named-destination/explorer routes, and own `pushState`/`replaceState` decisions per the URL contract. It lazy-loads `web/js/explorers/ledger.js` for `/ledger` and `web/js/ops.js` for `/ops`; create those two modules now as small named-destination pages ("delivered in Phase 9: Ledger/Ops") so no route 404s and 9-04/9-05 can replace their contents without touching the router. Keep unknown paths as the in-shell not-found view.
- `web/js/app.js`: wire router, schema-once, panel frame, Start and the route table; keep the existing session gate, identity renders, theme toggle, schema status and request-status footer working. Start renders the fixed question paths with target hrefs and disabled reasons computed from `/schema`; no old page set.
- `web/css/app.css` and `web/css/workspace.css`: scope bar, coverage strip, panel grid, state and badge presentation, 900 px single column; native elements first, visible focus, no animation/transition.
- `tests/workspace/browser.mjs`: re-export `../charts-cat/browser.mjs` so the workspace specs share the same loader and named skip reason.
- `tests/workspace/harness.mjs`: test-only static server for `web/` with the `_headers` CSP, `/` fallback to `index.html` for client routes, `/__test/stats`, and a controllable delay/release/error surface. `tests/workspace/stub-api.mjs` + `fixture.mjs`: deterministic same-origin API generated from the committed manifest counts, serving `/v1/me`, `/v1/analytics/{schema,summary,query,entities,activity,distribution,series,scores,conversations}` and `/v1/admin/status`; support default, `legacy` (old schema and `range too wide`) and `missing-feature` scenarios, admin/member roles, and deterministic empty/error/cancel controls. It is test-only, lives under `tests/`, is never shipped and is not imported by product code. Use no `/tmp`.
- `tests/workspace/engine.test.mjs`: pure checks for view-spec round-trip and canonical `p<n>`, scope-override precedence, registry validation (a registered preset whose panel id is missing fails; an unregistered preset resolves to a named destination), chooser filtering against a schema, panel-state transitions including `cancelled`, saved-board URLs, and Follow probe/ack semantics (ack advances only on success; a new probe counts only after the acknowledged watermark). `tests/workspace/start.test.mjs`: Chromium spec that opens `/`, checks every question path's href or disabled reason, opens delivered paths and named later destinations, exercises a `win=all` and a long finite `from`/`to` deep link plus Back restoring scope/filters/panels, and saves/reopens a named board. Assert `data-state`/`data-idle`, URL end state and at most four in-flight requests; no fixed sleeps; skip with `SKIP_REASON` when the browser is unavailable. Panel-state rendering is proven with 9-03's panels and again by 9-06.

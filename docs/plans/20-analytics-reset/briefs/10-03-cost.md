## Goal

Deliver the Cost preset so model, harness and session-repo cost investigations show their real populations, unpriced and lower-bound values stay visible, numeric eligibility is honest, and a join the server does not offer is named instead of being faked.

## Contract

- Cost preset panels (DESIGN.md): `trend-columns`, `rank`, `treemap`, `dist-ranges`, `dist-hist`, `dist-ecdf`.
- CONTRACTS.md 17.3: `cost_usd` is the priced-at-read sum with `unpriced_calls`; a partially priced group is a lower bound, an all-unpriced group is `null` (never 0); session cost is `null` when every call is unpriced. Direct `repo_id` on usage facts is empty for compatibility; the derived `session_repo` lens is the only honest repo attribution. Time `session_repo`/`session_model` are served only once `/schema` publishes them; until then a cost split by them is `unsupported_join` with a reason, not an empty group.
- CONTRACTS.md 7.2: `/query` returns `rows:[{k,v,t}]`, `bucket`, `requested_bucket`, `bucket_step`, `coarsened`, `window`; `/distribution?measure=&grain=call|conversation&dim=model|harness|session_model|session_repo` returns per-group `n`, `unpriced`, `min/p25/median/p75/p95/max`, `bins`, plus `group_n`, `omitted_groups`, `omitted_n`, `omitted_unpriced`; `/summary` gives window totals including `model_calls`, `unpriced_calls`, `cost_usd`.
- CONTRACTS.md 17.3.1: a measure or lens not published for the grain is 400 `unsupported_join` with `reason` and `try`. The UI must not request it.
- CONTRACTS.md 17.5: no dual axes, legend for two or more series, zero-based bars, units/time basis, a table for every chart, a filter never repaints a surviving series.
- `(mixed)`, `(none)`, `(multi)` and `unknown` are distinct published groups; never merge them into `(other)` or drop them.

## Changes

- `treemap.js`: a shared categorical treemap panel. Grain time, measure (default `cost_usd`), two schema-published dims (parent, child; default `harness`→`model`); `/query` with both dims and `bucket=none` or `day`; feed `<yk-treemap>` parent rows and child values. Keep a table; label the measure, unit, population and any omitted/`(other)` group. The panel refuses a dim pair `/query` does not publish for the measure with the unsupported reason and the `try` value. It is reused by Tools.
- `mix.js`: a shared composition panel. `/query` or `/distribution` with one measure and one/two published dims; `<yk-bars type="stacked">` (or `percent`) with a mode chooser. Show `unpriced`/omitted groups and keep `(mixed)`/`(none)`/`(multi)`/`unknown` separate. It is reused by Tools for hook-event composition.
- `p10-cost.js`: register the `treemap` panel and the `cost` preset with canonical preset specs. Cost reuses 10-01's already-registered `trend-columns`, `rank`, `dist-ranges`, `dist-hist` and `dist-ecdf`; register only `treemap` here and do not duplicate the shared panels. Defaults: `cost_usd`; split `model`; treemap `harness`→`model`; distribution `grain=call`, `dim=model`. The preset therefore names only ids that exist once 10-01 and this unit have loaded.
- Cost-specific request rules, applied in the shared panels through their specs/choosers where possible and in `treemap.js`/`mix.js` otherwise:
  - `/query` cost dims are the measure's published dims (`model`, `harness`, `conversation_id`, plus `hour_of_day`/`weekday` only for the heatmap). Never offer a direct `repo_id` cost split as if it had values: the contract says usage rows carry an empty direct repo. Instead the cost panel's repo view is the `/distribution` `session_repo` view (counts, medians, unpriced), and a repo *cost total* is `unsupported_join` with “session_repo is not served on /query for cost” and the distribution alternative.
  - Never derive a cost value from hook events or tool counts. A cost-by-tool or cost-by-tool-kind request is `unsupported_join`, named, with the supported “hook_events by tool” view offered as `try`.
  - Preserve `unpriced_calls`: request `/distribution` for the displayed grouping when the chart is a distribution; for a total/trend, request `/summary` for the same window and show “lower bound, N unpriced calls” or “all N calls unpriced; no priced cost” instead of `$0`. A zero price with priced calls is a real zero and is distinct from all-unpriced.
  - Show `omitted_groups`/`omitted_n`/`omitted_unpriced` and the `population.unit`; do not blend calls, sessions, files and content hashes.
- `cost.css`: only the notes/labels for pricing and population; no duplicate colour values.

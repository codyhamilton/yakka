## Problems / deviations

1. **Repo cost view is a named alternative, not a mounted `/distribution` view.**
   The brief wants the cost repo view to be the `/distribution?dim=session_repo`
   view, but 10-01's `dist-ranges`/`dist-hist`/`dist-ecdf` pin
   `DIST_DIMS=['model']` and this unit must not edit them. The Cost preset keeps
   its six catalog panels; `treemap.js`/`mix.js` name the distribution
   alternative and refuse a `/query` repo cost total instead of faking one.
   Carried: 10-04/10-05 or a later unit must add `session_repo` to the
   distribution lens list to mount the view.
2. **The stub `/query` ignores a second `dim`.** The committed fixture returns
   rows keyed only by the first dim, so the browser treemap shows parent totals
   and says `The server returned only the harness dimension; child cells mirror
   the parent totals.` The two-level mapping is proven with synthetic
   `k:[parent, child]` rows in the unit test. Gate: the workspace stub needs
   two-dim `/query` rows for a full browser two-level proof.
3. **`p10-shared` trend/rank totals do not print lower-bound/unpriced.** The
   brief asks a total/trend to request `/summary`; `trend-columns` and `rank`
   are 10-01 panels kept untouched, so only the treemap carries the `/summary`
   pricing read-out. `dist-ranges` already prints per-group unpriced and the
   "unpriced cost is a lower bound, never $0" note. Reported, not edited (a
   genuine shared-panel gap).
4. **Contradiction named, not resolved silently.** The p10 fixture publishes
   `session_repo` for `cost_usd` on the time grain, while the brief says a repo
   cost total is `unsupported_join` because `session_repo` is not served on
   `/query` for cost. I followed the brief: the chooser hides and the loader
   refuses it. If the server is meant to serve it once `/schema` publishes it,
   the brief's explicit repo rule should be revised.

# 9-05 — Ops explorer

Status: `over budget` (deliverable complete; concerns and the handoff are named below).

## What changed

- `web/js/panels/ops-footprint.js` — the `ops-footprint` entry (`grain: 'tenant'`,
  `requests()` = `GET /v1/admin/status`, read-only `load()` over the shared
  transport/scheduler under one state key) plus pure mappers/formatters for
  bytes, Unix seconds, counts with units, failures, rescore progress and the
  200/401/403/error status mapping. The renderer shows version, scoring,
  server volume only when supplied, and one block per tenant: facts,
  compaction, footprint bytes and counts, verdicts, scored content, score rows,
  rejections by stage, the server-capped recent failure list, and rescore
  state/times/error. Every tenant is separate; nothing is summed. A tenant
  `error` is shown for that tenant only. Absent fields are named
  "not supplied" rather than drawn as zero.
- `web/js/ops.js` — replaces the 9-01 placeholder: loads `/css/ops.css`
  idempotently, registers the entry, mounts one 9-01 panel frame and renders
  the mapped snapshot into the frame body. It does not create a route, guess an
  admin role, or call `POST /v1/admin/rescore`.
- `web/css/ops.css` — tenant blocks, tables and definition lists, right-aligned
  tabular numerics, focus outlines and a single-column/scrollable-table layout
  below 900 px. No animation or transition.
- `tests/workspace/ops.test.mjs` — 8 pure checks and 5 Chromium specs over the
  workspace harness: admin stub status, full status via a test-only
  intercepted response, member 403 with a request log, 500 + retry recovery,
  and a real aborted load settling `cancelled`.

## Deviations

- The shared `panel-frame.js` has no body renderer. Since it is not an owned
  path, `ops.js` keeps the frame for state/`data-idle`/basis/population/retry
  and renders the panel body itself from the entry's mapped result.
- The registry validator requires a non-empty chart name from `CHART_NAMES`,
  but this panel is table/definition-list only. The entry is registered with
  `charts: ['bars']` solely to pass validation; no chart is drawn. See the
  gate below.
- The committed stub's `adminStatus()` returns only `version`, `scoring` and
  `tenants: [{id,name}]`. The admin browser spec therefore asserts those and
  the explicit "not supplied" text; the full-shape assertions use a page-level
  intercepted `/v1/admin/status` response in the test only (no product branch).
- Error/cancelled were not driven by harness controls because the harness has
  no admin-status delay/error/cancel scene and is not an owned path. Error uses
  a test-side 500 interception; cancelled uses a real aborted product transport
  in the browser plus a unit check.
- Expected 403/500 responses make Chromium log the failed resource load. Those
  specs assert zero page errors and zero CSP violations; the other specs assert
  fully clean diagnostics.

## Known problems

- `app.js:renderExplorer` neither awaits the explorer render nor calls a
  `destroy()`/abort seam on navigation. Leaving `/ops` while the status request
  is in flight leaves that request to finish (no DOM leak, no visible error).
  Cause: the shell has no explorer teardown hook; reported, not fixed here.

## Goal

One shell whose visible tenant, window, repository, kind, timezone, commit controls and retained-record counts are the only source of scope for every analytics route, with the reserved `tenant` URL field, one frozen read context per generation, honest loading/error/legacy count states, and V5 navigation. This is the phase’s shell half.

## Contract

Settled by DESIGN.md lines 47–81 and 99–160. Implement literally; the short list below is a checklist, not a replacement.

- **ScopeState** is `{tenant, win, from, to, tz, filters, exclude, cohorts, cmp, panelSpecs}`. Add **reserved** URL field `tenant`; never put it in `filters` or `unknown`. Collector selection precedence: a URL tenant found in `/v1/me.tenants` → valid remembered tenant → first active owned tenant. Foreign, deleted or pending URL tenant **stops reads** and shows “This tenant is unavailable to your account.” with a “Choose a tenant” control; never silently fall back. A missing initial tenant is canonicalized with `replaceState`. Every later committed scope edit pushes exactly once. Back/Forward restores inputs and results without another push. Single-tenant users still see the selector and immutable ID. No cross-tenant aggregate option.
- **Direct/local modes:** read-only field “Local collector”, no fabricated `/me` identity. Bearer-only remote shows “Token-bound tenant” and hides management writes behind “Sign in to manage account”. Do not probe IDs. A supplied URL tenant cannot override credential isolation.
- **Window freezing:** freeze relative bounds once per applied scope generation using the read-context clock. APIs get absolute RFC3339 `from`,`to`; never `win`. `win=all` sends `all=1` and a frozen `to` with no `from`. Custom input uses the displayed IANA timezone and inclusive `[from,to]`; never interpret wall-clock input in another zone; reject nonexistent/ambiguous DST wall times with exactly “Use an unambiguous time in the selected timezone.” The 24 hours option writes `win=1d` (read old `24h` URLs compatibly); 7d/30d/90d are elapsed durations.
- **Tenant change:** commit immediately; cancel scheduler generations, close inspectors, stop Follow, clear selections/cohorts/cursors and prior entity payloads **before** new reads. Preserve window/timezone; clear repo/kind/other entity filters and per-panel scope predicates; preserve panel chart/measure selections. Re-fetch schema/facets/counts under the new tenant; clear tenant-sensitive caches. On a detail route navigate to its parent list (`artifact`→`/ledger`, session detail→`/sessions`, plan detail→`/plans`) under the new tenant. Navigation and question-path links propagate committed scope unless their label promises another window; those preserve tenant. Saved boards cannot restore a tenant the user cannot access.
- **Lifecycle revalidation:** after lifecycle operations and on window focus/`pageshow`, revalidate `/me` lifecycle_state/generation before tenant reads. If the remembered generation changed or the tenant disappeared, clear that selection and all tenant-sensitive caches and require explicit re-selection; never automatically choose a different tenant. Preserve existing cross-tab invalidation notices and pending-state suspension.
- **Panel overrides:** panel-local time/repo/tenant/kind overrides may not shadow the visible global bar. If all such saved overrides agree and the global field is absent, promote their common value once by `replaceState` and remove it from `pN`; a global value always wins. Conflicting overrides block affected panels with exactly “Saved panel scope conflicts with the global filters. Reset panel scope.” Reset removes only those override fields from `pN`; keep other advanced URL state. Do not reopen cohort/attribution semantics.
- **C1–C11** are the table at DESIGN.md lines 117–129. Copy labels/options/defaults/URL fields and the exact inline strings. Native labeled controls, not chip dropdowns. Inputs keep a local draft until Apply. Tenant commits immediately. Show literal “Unapplied changes” beside Apply while dirty. URL and bar always describe committed results, never relabelled draft.
- **Counts strip** (DESIGN.md lines 63–79): on every analytics route show loading “Counting retained events…”; success `Events matching filters: {matched.events} · Rejections: {matched.rejections} · All retained events in tenant: {tenant_total.events}` plus `Counts checked {local timestamp}`; error “Event counts unavailable” + Retry counts; legacy schema without `event_counts` “This server cannot report retained-event totals.” + link to Ledger. Never zero, sample or guessed totals. A new data notification or Refresh clears page cursors and re-requests counts and first pages. Expose `currentEventCounts()` so the Pulse/Ledger unit can render its own denominators without touching `app.js`.
- **V1/V4/V5:** exact region heights (identity row 46px; analytics nav 32px; account nav 32px; heading 32px; filter row minimum 44px; count line 32px), full width, 12px gutters, no max-width wrapper. No decorative chips, no default 30d removable chip, no centre alignment, no white chart surfaces, no pills/gradients/animations. Nav row 1: Start, Pulse, Trends, Cost, Quality, Tools, Workflow, Compare, Scatter, Plans, Sessions, Ledger, Operations in that order. Nav row 2: Tokens, Tenants, Membership, Settings, Device approval in that order, with hrefs `/profile#tokens`, `/profile#tenants`, `/profile#membership`, `/settings`, `/device`. Brand → Start; Theme at the right of the tenant field. Active link `aria-current=page`; anchor links `aria-current=location`. Row 2 reaches the existing routes; do not build the account console and do not add a lifecycle link to the nav.
- **T base:** every data/header row 30px, single line, ellipsis with full-text title; left aligned; tabular numerals for numbers; buttons/selects/inputs minimum 28px; panel padding 8px, gap 8px, border 1px, radius 2px, no shadows. Minimum-width tables scroll inside their panel, never widen the document. Metadata loading/failure states use the exact strings at DESIGN.md line 131.
- Do **not** implement phase 2 captions/P1–P10/F1–F6 completeness or phase 3 account screens. Existing panels keep current render paths. Where an existing panel cannot honour the new global scope, it may show only an F refusal; the phase-1 minimum is a truthful refusal, not a chart rewrite.

6. **`core/request-scheduler.js`** — add a way to cancel every in-flight/queued request for a tenant generation (e.g. `supersedeAll()`), used before new tenant reads. Do not change the four-request cap, deduplication or one-response-per-waiter behaviour.

9. **`core/saved-boards.js`** — keep the URL as the source of truth. Opening a board navigates to the stored URL; authorization happens in the shell so an inaccessible stored tenant shows the unavailable state rather than a silent fallback. No server storage.
10. **`core/follow.js`** — keep probe/acknowledge semantics. The shell must destroy Follow on route teardown and on tenant change; no other auto-refresh.
11. **`core/scope-controls.js` (new)** — `createScopeControls` implementing C1–C11, the draft/Apply model, custom From/To validation, facet loading/failure/empty states, Reset/All history/Refresh/Theme, C11 details, “Unapplied changes”, and the canonical push/replace decisions. Fetch facets from `/v1/analytics/facets` with tenant and frozen window only (other filters do not narrow options). Do not render time/repo/kind on account/login/callback/device/not-found/lifecycle routes.
12. **`core/event-counts.js` (new)** — `createEventCountStrip({transport, readContext, allowRefresh, onRetry})` plus `currentEventCounts()`. Request `/v1/analytics/event-counts` through `readContext.paramsFor()`. Implement the exact loading/success/error/legacy states above; success also stores `checkedAt` and the matched/tenant totals for `currentEventCounts()`. On a new generation, discard the prior snapshot before requesting. `Retry counts` repeats the committed scope, not a draft. Never show a count for a failed or absent response.
13. **`app.js`** — remove `renderScopeBar`'s display-only bar and replace it with: header tenant/theme mounting; one filters + counts region at the top of every analytics render (start, board, named, explorer); authorized tenant resolution and unavailable view; initial canonicalization; render-generation checks before every DOM write; tenant-change teardown/navigation rules; panel-override promotion/conflict; active nav marking; Follow destruction; saved-board authorization; and the count strip wired to Refresh. Keep the existing board/explorer/account dispatch and question paths. Pass the frozen context to explorers through the existing `readContext` option and tenant through the existing option.
14. **CSS** — `app.css` owns the V1 top/nav/heading dimensions, full-width body/main and left alignment. `workspace.css` owns the 30px row base, panel 8px padding/gap, control minimums and the count line height; keep existing panel/state/chip hooks working. New `scope-controls.css` owns the filter form layout, the two-row wrap, native select/input/button sizing, the custom From/To row, the Advanced scope details rows, and the loading/error inline text.

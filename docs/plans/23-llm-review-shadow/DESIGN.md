## Solution Shape

Extend the existing shared REST/MCP review orchestrator and tenant stores. The server owns schemas, call policy, findings, paging and spend; the shim continues bounded local collection only. General effort/tags/store parameters replace trial capability gating. Persisted synthetic activity runs on the real deployed server under a dedicated tenant/key; `store=false` serves secondary ephemeral use. Add a bounded authenticated synthetic-tenant reset that erases both tenant files and attributed global assets. Trial tooling verifies full history, uses complete filtered reads and keeps explicit paid-spend authorization separate from zero-call preflight.

### Domain: review call and cached response (Decisions 3–6)

Owner: `internal/review`, REST `POST /v1/reviews`, server-defined MCP `review_change`, `internal/store`/`internal/ingest`. Both transports share validation, response fields and effects. Existing capture, criteria, disclosure checks, fixed provider endpoint, bounded retries, non-gating workflow use and `read_write` authorization remain in force, including for unpersisted spend.

| Optional argument | Contract |
| --- | --- |
| `effort` | Omitted means `high`; exact strings `high`, `xhigh`, `max` only. Null, empty, other values and wrong types are argument errors before spend or storage. Valid for any supported review mode; neither trial identity nor a deployment toggle is required. Persist configured effort (`high`), requested effort (including default resolution) and effective effort; send effective effort explicitly on every provider attempt. |
| `tags` | Omitted means `[]`. At most 16 strings, each 1–96 ASCII bytes matching `[A-Za-z0-9][A-Za-z0-9._:/=-]{0,95}`; case-sensitive. Reject wrong types/null, controls, whitespace, invalid charset, overlength or overcount before effects. Count the submitted list before deduplicating; canonicalize accepted values as a sorted unique set. Apply existing metadata disclosure checks; tags are visible metadata, never provider prompt content. |
| `store` | Boolean, omitted means `true`; null/wrong types rejected. `false` returns full validated review data, never writes review records, captured inputs or findings and never enters list/search/quality pathways. Skip **all dedupe/cache reads and writes**, including persistent execution claims. Each explicit call is independent paid work if it reaches the provider; transport ambiguity must never cause an automatic replay. |

`YAKKA_REVIEW_TRIAL_ENABLED` is dropped entirely: remove its config field, env parsing, availability branch, documentation and fixture expectations. It meant “permit historical trial effort overrides”; per-call validated effort now does that job and stored effort makes overrides auditable. `YAKKA_REVIEW_EFFORT` remains a high-only server default/validation setting; it never limits a valid per-call override. `YAKKA_REVIEW_MODEL` stays server-only and must equal `claude-haiku-5-5`; no client model parameter. Configured/returned reviewer ids remain recorded. No live provider capability is claimed by this amendment.

For `/v1` additive compatibility, old `trial{manifest_hash,case_id,effort}` remains only as a deprecated input adapter, with its existing syntax/range validation but **no env gate**. It translates to the same effort and general tags, preserves legacy manifest/case/profile read fields and can resolve old execution claims. Top-level effort plus a conflicting legacy effort is an argument error; equal values are accepted. The adapter generates `effort:<level>`, `manifest:<hash>` and `case:<sha256-of-case-id>` tags, unions them with caller tags, and validates both the submitted and merged sets against the same bounds. Original cached legacy records remain immutable and untagged; a compatibility duplicate audit row may carry these mapped tags and the canonical pointer. New clients never send `trial` or a special run/label argument. Old stored records and all old read filters remain readable; absent tags mean an empty set. Effort/tags/store are sufficient for new requests. Legacy identity is not a prerequisite for any effort.

For `store=true`, lookup the original review by tenant and execution key directly, without a 500-row scan. Execution identity keeps capture, criteria, build models, reviewer model, effective effort and policy/ordinary review identity. For ordinary requests with an empty canonical tag set, preserve the exact pre-upgrade execution-key serialization/hash, including its ordinary profile, so existing untagged paid work remains cached after upgrade. Nonempty tag sets use a distinct versioned key containing the canonical set, so independently tagged experiments remain distinct; they never collide with untagged keys. Legacy-key fallback is allowed only for a legacy-adapter request whose canonical merged tag set equals exactly the three deterministic adapter tags (no extra caller tag), with matching stored legacy manifest/case/effort and every other old identity field. A request with any additional tag uses only the new tag-sensitive key and must not fall back to a legacy key. New requests without the legacy object never use this fallback. A cache hit returns the **full cached review in the fresh response shape**, even when `detail` is omitted/receipt: `status=skipped_duplicate`, `cached=true`, `original_review_id`, and `original_status`, with original result, coverage, finding counts, model/effort, tags, attempts and usage/cost evidence. `reason` remains the original id for old clients. Original payload/status are never misrepresented as a new successful review; no new provider cost is incurred. Fresh default receipts retain their existing size; `detail=full` gives their full review. `store=false` always gives full review regardless of detail. Captured content is never returned.

A claim whose original request is still running or whose provider outcome is unknown cannot invent a cached review. Return `in_progress` or `outcome_unknown` with original id and `cached=false`, no result, no second provider call; reserve `skipped_duplicate` for a completed stored original, including stored terminal errors whose result may be absent. Missing/corrupt originals fail explicitly (`cache_unavailable`), never become an empty successful cache hit. Completed duplicate responses have REST/MCP parity in every payload field. This replaces the old Phase 5 reference-only parity interpretation; it does not reopen Phase 5.

Zero-call refusals do not consume execution claims. Stored duplicate audit rows may remain for compatibility, but are marked as references with no new attempts or charge; reports count the canonical original once. A returned original's historical cost is evidence, never incremental duplicate spend. Changing effort creates independent identity. Concurrent equal stored calls and restarts preserve the original claim.

For `store=false`, keep only a **content-free `review_usage` fact in the caller's tenant**, outside `review_run` and quality/conversation/hook/facet aggregates: random usage id, configured/returned model, configured/requested/effective effort, tokens, estimated cost/pricing identity, timestamp, validated tags, `store=false`, attempt/status and unresolved-reservation accounting. No repo/plan/session/capture identity, prompt, criteria, findings, error bodies or content-derived hashes. It enters an explicitly named tenant review-spend measure, never work_cost or quality counts. Synthetic callers use the synthetic key even for these facts. Spend reservations/in-flight limits still apply under fresh non-cache identifiers, attributed to the tenant, with conservative charge for unknown outcomes. `dry_run` writes none of these facts or reservations and makes zero provider calls; it wins over store/detail and validates configuration, allowlist, effort and disclosure readiness first.

### Domain: complete tenant-bound reads (Decisions 1 and 5)

Owner: REST GET reviews, new server-defined MCP `list_reviews` (read scope, read-only, no local readers/actions), store review queries. The shim learns the tool through the registry; no tool-name/schema logic is added to the client.

Both entries accept the existing repo_id/plan/phase/kind/status/effort/profile/manifest_hash/since filters, `detail=full`, `limit` and `cursor`; add exact tag filtering: repeated REST `tag=value`, MCP `tags:[value,...]`, with the same 16 × 96 bounds. Multiple tags mean **ALL**, conjunctive with all other fields. An empty filter matches all tenant reviews, including old untagged records; a tag filter never matches an untagged record. Invalid filters return an explicit argument error. Preserve the existing REST `reviews` array and add `next_cursor` (opaque string or null) and `complete` (boolean); MCP returns the same data object. Limit is page size (default 100, range 1–500), never a complete-read ceiling. Other analytics endpoints retain their limits.

The first page fixes an insertion high-water mark in the tenant review store; subsequent pages use stable descending `(ts, insertion_id)` ordering with a strict last-key boundary, never offsets. Bind cursor version, authenticated tenant, route, canonical filters, detail and high-water mark. A cursor cannot select or authorize another tenant. Malformed, mismatched or unsupported cursors fail explicitly (REST 400 / MCP invalid arguments); after reset they cannot revive a tenant. Page size may change without changing selection. Rows appended later, including backdated ts rows, cannot enter the fixed read. Existing review rows and tags are immutable during this walk. A reset or store generation change invalidates the walk rather than silently dropping rows.

Every nonterminal page has `complete=false` and a progressing cursor; the exhausted page has `complete=true,next_cursor=null`, including exact-multiple and empty populations. A decode/query/corrupt-row error fails the page; do not silently skip malformed stored review rows. No source row can be silently omitted. Consumers verify protocol consistency and unique row identities; cycles, missing completion metadata, request failures, early interruption or an operator safety ceiling produce a nonzero/incomplete result, never a complete report. Saved trial exports carry filters, high-water identity, exhausted-page evidence and counts; a legacy bare 500-row response cannot certify completeness. No fixed total row ceiling is substituted for paging.

### Domain: synthetic tenancy and complete disposal (Decisions 7 and 8)

Owner: existing registry/auth/tenant lifecycle, store manager, review reservations and admin route. Yes, the real deployed Yakka server is the sound trial target and matches the original remote-review intent. Its provider credential remains a Fly secret. Operators and local tooling use only Yakka `wk_` auth; fixtures/local servers are for tests.

Operator preparation after implementation: sign into the existing owner session; use `POST /v1/tenants` to create a dedicated tenant named `shadow-trial` (or `synthetic`); issue a separate `read_write` key with existing `POST /v1/tokens`. Record the returned immutable tenant id, not just its display name. Add `<synthetic-tenant-id>/<repo_id>` to `YAKKA_REVIEW_REPOS` through the normal operator-controlled configuration process. Confirm the key's identity with whoami before sending any captures; abort a real-work tenant mismatch. Reports and evidence use that same tenant/key. Provisioning, config changes, deployment and token handling are later operator acts; none occur in this design task.

Synthetic reviews use `store=true`: tags, caching, paging, tracking and costs work normally within that tenant. A real-work bearer or its selected owner-session tenant must see none of the synthetic tenant's reviews, findings, search results, usage, analytics or cost rollups. Shared owner identity does not combine tenants. There is **no separate synthetic-spend counter**. The existing provider-wide rolling safety cap still accounts for all tenants; it is an operational shared budget, not real-work tenant analytics or permission to reveal another tenant's spend.

**Answer to Cody today:** CreateTenant exists, but there is no DeleteTenant API or registry method. Docs describe deleting a tenant as deleting `<data>/<tenant>/`, containing ledger.db, blobs/, pending/ and archive/ (also landed review-inputs/). That sentence describes storage shape, not an implemented cascade. Token registry, sessions, owner/name rows and global review reservation/claim state live alongside tenant directories. Raw directory removal leaves orphaned tokens/owner rows; still-valid tokens can lazily recreate the directory. **Removing a tenancy does not currently auto-clean all assets via an API.** User sessions are global to the signed-in user rather than owned by one tenant.

Add remote-only **`POST /v1/admin/tenants/<tenant-id>/reset`**, admin session + same-origin + JSON, body `{confirm_tenant_id:<same id>}`. Bearers (even read_write), non-admin sessions, local mode and mismatched confirmation are refused without effects. This bounded reset **deletes the synthetic tenant identity as well as its data**; recreating the experiment means a new tenant id and key. No UI or MCP delete tool is required. It supports tenants freshly created after the ownership-aware lifecycle format lands. Legacy tenants without a trustworthy creation/ownership marker return 409 `legacy_tenant_cleanup_unsupported` before destructive work; it is not a general retroactive DeleteTenant promise.

The lifecycle contract blocks all admission, new token issuance/device redemption and background writes for that id before erasure; drains or cancels in-flight reviews and waits for their final reservation settlement; stops screening/rescore/queued writes; closes readers/writer/WAL/locks; and evicts open-store and in-memory claim caches. Remove the whole tenant directory (facts, reviews, findings, captures, tags, usage, rollups, blobs, pending, archive, review-inputs and temporary files), all registry tokens including revoked/expired entries, owner/name/creation entries, approved device grants and attributed global execution claims/reservation records. Retain user-global sessions, other tenants' grants/tokens/state, shared admission policy and provider configuration.

All new claims and spend reservations, including store=false calls, carry explicit tenant ownership and a format version. A fresh tenant's creation marker guarantees no pre-upgrade unattributable assets. Existing opaque legacy claims remain unchanged and cannot be guessed, reverse-hashed or bulk-deleted; supporting their tenant deletion needs a separate migration design. Before removing attributed rolling spend, transfer only timestamp/amount into a non-attributable provider-wide safety accumulator until normal expiry, with no tenant id, key, review/usage id, tags or reverse mapping. Thus reset does not refund shared budget or leave a tenant asset. This accumulator is never a tenant analytics source.

Reset returns 204 **only after** zero target rows/objects/identity references remain, including its temporary deletion journal; 409 `tenant_busy` before beginning if work cannot be safely quiesced, otherwise failure is non-success and the id stays unavailable while durable bounded cleanup resumes after restart. Never report completion for partial removal. Do not keep a permanent target tombstone after success: unknown/unregistered tenant ids must be refused by every lazy-open/admission path. Repeated reset of an absent id is 204; it cannot recreate files. Test restart/crash boundaries and concurrent attempts to ingest, review, issue tokens, redeem device grants and read through old cursors. Other tenants remain readable and byte-equivalent in their persisted data.

### Domain: trial preparation, execution and evidence (Decisions 2, 9 and 10)

Owner: `tools/shadow-review-trial`, operator run evidence under `docs/lab/RESEARCH/`. Keep the landed manifest/comparator eligibility, capture leakage exclusions, frozen criteria, seeded paired order, retry limits, adjudication rubric, build-model strata and honest shortfalls. This amendment changes retrieval, inputs and preparation, not the comparison's meaning.

Duplicate replies already contain the canonical review, so no follow-up GET is needed to see findings. Reconcile original id exactly once; duplicate receipts do not add completed cases or cost. Unknown/in-progress calls remain visible and are not blindly replayed. Usage totals use only this trial's canonical attempts/usage, addressing the landed unrelated-record accounting risk rather than summing the tenant's entire history. Preserve attempted/eligible/status/finding/adjudication denominators and per-effort completion and eligible shortfalls. Target: **at least 50 distinct completed valid Haiku reviewed changes per effort high/xhigh/max**, paired across levels when possible, common completed intersection separately reported; never pad or count failed/duplicate/mismatched-model reviews as new completions.
